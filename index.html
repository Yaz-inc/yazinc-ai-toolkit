Practical setup guide

Use the toolkit in any project.

Keep this repository as the canonical source. Connect or copy only the skills your agent environment needs.

1 Get the toolkit

Clone once, then keep it current

Clone the repository into your development workspace. Existing installations should pull the latest changes before starting a new engagement.

git clone https://github.com/Yaz-inc/yazinc-ai-toolkit.git
cd yazinc-ai-toolkit; git pull
2A Cursor

Link the complete library

Run the included PowerShell helper from the toolkit root. It links the canonical skills folder into your Cursor profile.

.\scripts\link-skills.ps1

Restart Cursor or open a new chat after linking.

2B Codex

Install selected skills

Copy a skill folder into your Codex skills directory. Repeat this for each capability you want Codex to discover automatically.

New-Item -ItemType Directory -Force "$env:USERPROFILE\.codex\skills" | Out-Null; Copy-Item -Recurse .\skills\test-software-app "$env:USERPROFILE\.codex\skills\test-software-app"

Start a new Codex task after installing or updating skills.

2C Claude Code

Install personal or project skills

Copy a skill to your personal Claude directory for every project, or into a project's .claude/skills directory when it belongs only to that repository.

New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills" | Out-Null; Copy-Item -Recurse .\skills\test-software-app "$env:USERPROFILE\.claude\skills\test-software-app"

Invoke it with /test-software-app. Claude Code also supports project skills at .claude/skills/<skill-name>/SKILL.md. Official Claude documentation.

3 Project use

Invoke by outcome

Name the skill in your request, use the platform's direct command, or ask the agent to inspect the toolkit and select the best skill before beginning.

Use $test-software-app to plan and run a five-stage audit of this Laravel application.
Use $data-profile-clean-validate to profile this dataset without modifying the source file.

Close the learning loop

Turn project experience into the next reusable skill.

When a workflow will be useful again, load $extract-to-toolkit. Generalize the lesson, remove secrets and client-specific data, record provenance, then update the catalog and registry together.

Read the contribution workflow Open the extraction skill

Non-negotiable rules

  • Never commit secrets, credentials, or client data.
  • Keep one skill focused on one repeatable job.
  • Record the source project and extraction date.
  • Update INDEX.md and projects/REGISTRY.md together.
  • Verify behavior before claiming a skill is ready.
